# 優惠課程類型正規化設計

## 目標

課名尾端有無「優惠」標記，應視為相同的課程類型。例如「現代小品」與「現代小品〈優惠〉」都歸類為「現代小品」。

## 行為

- 前端與 Apps Script 後端解析課程類型時，移除課名尾端獨立的「優惠」標記。
- 支援常見括號寫法：`〈優惠〉`、`<優惠>`、`（優惠）`、`(優惠)`、`【優惠】`，以及尾端未加括號的 `優惠`。
- 難度仍獨立解析；例如「A－空瑜 Lv.1-2〈優惠〉」歸類為「空瑜」，難度為 `Lv.1-2`。
- 原始 OB 課名、教室、課程代碼與 Class ID 不修改；老師最後選擇的實際 OB 課程仍由原本認領流程精準綁定。

## 安全範圍

- 不修改正式 Google Sheet 的資料、欄位或結構。
- 不執行同步、批次更新或資料遷移。
- 部署前須先取得使用者明確同意。

## 驗證

- 後端解析測試涵蓋一般課名與含難度課名。
- 前端解析測試涵蓋相同案例，避免舊資料或快取回傳未正規化名稱時再次拆分。
- 執行前後端完整測試與 Apps Script 語法檢查。
