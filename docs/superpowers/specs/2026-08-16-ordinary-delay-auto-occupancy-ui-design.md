# 一般代課延後自動占用顯示修正設計

## 問題

一般代課選擇延後 15 或 30 分鐘時，前端已能算出會占用的下一堂代課，後端也會在送出時原子保留該堂；但目前前端只更新文字摘要，沒有同步下一堂的勾選與可用狀態。因此下一堂仍會留在可選清單，甚至可能與原堂一起送出，最後被後端以「同一批不可同時領取或重複占用下一堂課」整批拒絕。

## 核准行為

- 呈現方式比照特別課的「系統自動占用」。
- 老師勾選原堂並選擇延後時間後，若預覽指出會占用下一堂：
  - 下一堂立即取消勾選。
  - 下一堂的勾選框停用，編輯區收起。
  - 下一堂卡片以灰色自動占用狀態呈現，顯示「系統自動占用」。
  - 下一堂不算可領課程，也不進入送出 payload。
- 若老師改回原時段，或改成不再衝突的延後時間，下一堂立即恢復正常可選狀態，但不自動重新勾選。
- 原堂摘要仍顯示實際開始、結束與需由管理員關閉 OB 的下一堂時間。

## 前端資料流

1. 一般代課卡片的勾選、處理方式或延後分鐘數改變時，先清除上一輪一般代課自動占用標記。
2. 從目前仍勾選的一般代課卡片讀取草稿，逐堂呼叫既有 `buildOrdinaryDelayPreview()`。
3. 收集每個合法預覽的 `occupiedSubstituteId`。
4. 對被占用卡片取消勾選、停用控制項、收起編輯器並套用與特別課一致的自動占用樣式與文字。
5. 重新計算送出按鈕狀態。送出時仍由既有後端重新核對正式 Sheet 與 CourseList，前端狀態不取代後端鎖定與驗證。

## 邊界處理

- 預覽為 `blocked` 時不標記任何下一堂，維持既有錯誤摘要並停用送出。
- 下一堂先前已被老師勾選時，必須取消勾選；它的草稿不保留為送出項目。
- 取消原堂勾選、切回直接認領、切換延後分鐘數或重新取得代課清單時，都要從目前狀態重新計算，不保留過期的自動占用標記。
- 特別課原有自動占用行為與後端一般代課占用邏輯不變。

## 測試

- 先新增會失敗的前端回歸測試，重現「原堂延後 30 分鐘時，已勾選的下一堂仍可選」。
- 驗證修正後下一堂會取消勾選、停用並顯示「系統自動占用」。
- 驗證改回原時段後下一堂恢復可選，但不自動勾選。
- 驗證送出 payload 只有原堂與 `startDelayMinutes`，不包含被占用堂。
- 驗證特別課自動占用相關測試仍通過，再執行完整前端與全系統測試。

## 正式資料影響

本修正只改 `index.html` 與前端回歸測試，不修改 `Code.gs`、正式 Google Sheet 欄位或既有老師資料。上線只需發布 GitHub Pages；不需要 `clasp push --force` 或建立新的 GAS version。
