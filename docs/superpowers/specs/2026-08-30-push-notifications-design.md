# Sherry Aerial PWA 即時通知設計

日期：2026-08-30  
專案：Sherry Aerial 教室管理 PWA

## 目標

在現有可安裝 PWA 加入 OneSignal Web Push，讓老師與管理員在網站未開啟時仍能收到必要通知。推播只補強既有流程，不改變請假、代課、關課、VVIP、OB 或薪資的資料契約與成功條件。

## 已確認通知事件

### 老師

1. 管理員按下「開放給勾選老師」後，只通知本次實際新增開放的老師；已在邀請中的老師不重複通知。
2. 老師成功領取一般代課或特別課後，通知該老師領取成功。
3. 老師的退出申請被管理員核准或駁回後，通知原代課老師處理結果。
4. 代課被其他老師先領走時不通知。

### 管理員

管理員收件人以目前仍在職且具有 `course_admin` 權限的帳號為準，現在應包含冠蓉與 Tako，不在程式中以姓名硬編碼。

1. 每日 22:30 第一次關課完成後，通知取消成功數、保留數、人工確認數與失敗數。
2. 22:30 檢核後，依 23:40 的最低成班門檻找出「只差 1 人」的隔日課程，產生一段可貼到社群的文字並通知管理員。
3. 每日 23:40 第二次關課完成後，通知取消成功數、保留數、人工確認數與失敗數。
4. 任一階段有失敗時，通知必須列出失敗課程；既有關課失敗 Email 保留作為備援。

## 社群文字

預設格式：

```text
明12:00劍潭蕃茄柔軟度開發
12:00晴光巧巧環
13:15劍潭蕃茄環
13:30晴光Lily舞綢
18:30劍潭Ariel舞綢
21:30晴光Nana 空瑜
各缺一，等到23:40
```

規則：

- 第一行以「明」開頭，後續行不重複。
- 課程依開始時間排序。
- 「只差 1 人」不是固定等於 1 人，而是 `最新人數 === 最低成班人數 - 1`：一般課 1 人、指定老師或 2 點課 2 人、雙人課 3 人。
- 場地租借／場租不納入。
- 場館優先使用 OB 回傳的 location；資料缺漏時明確顯示待確認，不自行猜晴光或劍潭。
- 老師與課名使用適合社群的短名稱；先支援使用者提供的蕃茄、巧巧、Lily、Ariel、Nana 顯示方式，其餘沿用清理 emoji 後的 OB 老師名。
- 管理頁以可編輯文字區呈現，管理員可修正後一鍵複製；系統不代發 LINE 或社群訊息。
- 沒有只差 1 人的課時，不顯示複製區，也不發「社群文字待貼」推播。

## OneSignal 架構

- 使用 OneSignal Web SDK v16 與 OneSignal REST API。
- `OneSignalSDKWorker.js` 只載入 OneSignal 的推播 worker；不得加入 `fetch`、Cache Storage 或離線資料快取。
- 前端登入或恢復登入後，向 GAS 取得公開的 OneSignal App ID 與一個不含姓名的穩定 `external_id`，再呼叫 `OneSignal.login(external_id)`。
- `external_id` 由 GAS 使用 Script Properties 中的私密 salt 與老師姓名雜湊產生；不把老師姓名、Email、PIN 或 session token交給 OneSignal。
- 登出時呼叫 `OneSignal.logout()`，避免共用裝置收到前一位老師的通知。
- OneSignal App ID、REST API Key 與 external ID salt 全部放在 GAS Script Properties。只有 App ID 可回傳前端；REST API Key 與 salt 永不回傳。
- GAS 以 `include_aliases.external_id` 精準寄送，老師事件只寄給該老師，管理事件只寄給目前具有 `course_admin` 的帳號。

## 授權體驗

- 不在載入頁面時直接叫出瀏覽器原生通知權限。
- 登入後在首頁顯示「開啟即時通知」卡片，說明會收到代課與管理待辦。
- 使用者按下「開啟通知」後才呼叫原生權限視窗。
- 已允許時顯示「通知已開啟」與關閉按鈕；已拒絕時顯示到系統設定重新開啟的說明，不反覆彈窗。
- iPhone／iPad 尚未從主畫面 PWA 開啟時，顯示「請先加入主畫面」引導，不呼叫無效權限視窗。
- Android、Chrome、Edge、macOS Safari 依功能偵測顯示支援狀態。

## 通知點擊目的地

- 新代課邀請：`?view=claim`
- 領取成功、退出結果：`?view=mysubs`
- 22:30／23:40 關課與社群文字：`?view=admin&tab=closureManagement`
- 前端啟動時解析 `view` 與 `tab`，仍先完成登入／session 恢復與權限檢查，再導向可用頁面；沒有管理權限時不得打開管理頁。

## 可靠性與安全

- 推播是附加通知，不得成為核心交易成功的前提。Sheet／OB 狀態轉換成功後才嘗試推播；推播失敗只記錄錯誤，不回滾已完成的核心操作。
- 關課執行本身拋錯時，排程仍寄既有失敗 Email，並盡力推播管理員。
- 關課推播以 `日期 + 階段 + 通知種類` 寫入 Script Properties 防重複；不新增或改寫老師資料工作表。
- 邀請只通知 `openInvitations_` 本次實際新增的老師，避免重複邀請推播。
- 所有前端傳入的收件人、external ID、管理員名單皆不可信；後端只由已驗證 session、帳號權限與交易結果決定收件人。
- OneSignal 未設定、服務暫時失敗或裝置未訂閱時，原本功能仍正常完成，前端顯示適當狀態。

## 資料影響

- 不新增 Sheet 分頁。
- 不修改既有 Sheet 欄位、索引或人工資料。
- 新增的設定與防重複狀態僅使用 GAS Script Properties。
- OneSignal 保存裝置訂閱與 opaque external ID，不保存正式 Sheet 課程內容；推播內文只包含完成操作所需的課程摘要。

## 驗證

- 後端單元測試：身份雜湊、精準收件、未設定降級、API 錯誤不回滾、邀請／領取／退出事件、22:30／23:40 摘要、只差一人規則、去重。
- 前端契約測試：worker 無快取、授權卡狀態、登入／登出身份綁定、iOS 主畫面引導、通知點擊導頁。
- 正式發布前：完整測試、OneSignal 測試使用者、iPhone 主畫面 PWA、Android Chrome PWA、管理員 22:30／23:40 模擬結果。
- 正式驗證只使用測試推播與程式 fixture；不得為測試而修改正式 Sheet 老師或代課資料。
