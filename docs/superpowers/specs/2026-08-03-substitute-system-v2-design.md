# 代課系統 v2 設計規格

日期：2026-08-03  
專案：Sherry Aerial Studio 代課系統  
前端：`sherryaerial-web/sub.html`  
後端：Google Apps Script + Google Sheets + Omcean Booking API

## 目標

在不改動既有試算表固定欄位索引的前提下，讓課程資料改由 Omcean Booking API 自動同步，並改善老師請假、領取代課、跨課程種類改課備註及重複領取防護。

本階段只處理代課模組，不納入薪資與其他內部管理功能。

## 使用者流程

### 請假老師

1. 從「老師名單」選擇姓名。
2. 系統從 `CourseList` 顯示該老師在同步期間內的課程。
3. 老師可勾選一堂或多堂課送出請假。
4. 每堂課建立一筆狀態為「確認中」的代課紀錄。
5. 已存在的同一位老師、日期、時段與課程不得重複建立。

### 代課老師

1. 選擇自己的姓名。
2. 查看狀態為「確認中」的代課課程。
3. 勾選欲領取的課程。
4. 系統依老師在 `CourseList` 中的授課資料判斷其平常授課大類。
5. 若原課程與代課老師的平常授課大類相同，可直接領取。
6. 若屬跨大類代課，必須填寫「改成什麼課」後才能送出。
7. 成功領取後，狀態改為「已領取」、寫入代課老師，改課內容寫入既有「備註」欄。
8. 不需要管理員核准，成功寫入後立即成立。

### 我的代課紀錄

老師可依姓名查看自己已領取的代課，顯示日期、時段、原課程、原老師及改課備註。

## 課程大類判斷

依課程名稱關鍵字正規化為下列大類：

- 空環
- 舞綢
- 空瑜
- 瑜伽
- 柔軟度
- 綢吊
- 其他

同一大類的不同等級視為相同種類，例如「空環 Lv.1」與「空環 Lv.2」不需改課備註。不同大類必須填寫改課內容。

若課程名稱無法辨識，歸類為「其他」。代課老師平常沒有該完整課程名稱時，視為跨類並要求備註，避免未知課程直接略過檢查。

## Omcean Booking API 同步

API 端點：

`GET https://api.omceanbooking.com/v1/calendar`

驗證方式：

`Authorization: Bearer <token>`

權杖只儲存在 Apps Script 的 Script Properties，屬性名稱為 `OMCEAN_API_TOKEN`，不得寫入前端、GitHub 或試算表。

同步範圍採「執行當天至下個月底」。例如 2026-08-03 執行時，日期範圍為 2026-08-03 至 2026-09-30。

同步規則：

- 排除已取消課程。
- 每頁最多 100 筆，使用 `start` 持續分頁，直到回傳不足 100 筆。
- 依 API 穩定 ID 去除重複資料；若缺少穩定 ID，以日期、時間、課程與指導者組合作為備援鍵。
- 每小時由時間觸發器自動同步一次。
- 提供管理用手動同步函式。
- 先完整抓取、驗證與正規化至記憶體，成功後才更新 `CourseList`。
- API 錯誤、回傳格式不符或取得零筆異常資料時，不清空既有 `CourseList`。
- 使用 `LockService` 避免同步與其他寫入操作互相衝突。

## Google Sheets 欄位契約

### CourseList

固定維持：

- A：日期
- B：時間
- C：課程
- D：指導者

現有程式索引保持：

- `r[0]` 日期
- `r[1]` 時間
- `r[2]` 課程
- `r[3]` 指導者

### 工作表1

固定維持：

- A：登記時間
- B：原老師
- C：日期
- D：時段
- E：課程
- F：狀態
- G：代課老師
- H：備註
- I：入系統
- J：代課編號

現有程式索引保持：

- `r[1]` 原老師
- `r[2]` 日期
- `r[3]` 時段
- `r[4]` 課程
- `r[5]` 狀態
- `r[6]` 代課老師
- `r[7]` 備註

J 欄為原本空白欄，命名為「代課編號」。新請假紀錄以 UUID 建立代課編號；既有資料不改寫。前端領取時以代課編號指定紀錄，不再只用日期、時段和課程猜測資料列。

## 後端安全規則

- `submitLeave` 與 `submitClaim` 均使用 `LockService.getScriptLock()`。
- 寫入前重新檢查紀錄狀態。
- 同一代課編號只有第一位成功取得鎖定且狀態仍為「確認中」的老師能領取。
- 代課老師不得領取自己原本的課程。
- 跨大類時後端也必須驗證備註，不能只依賴前端必填。
- 所有輸入需檢查空值、JSON 格式、老師姓名與課程是否存在。
- 回傳統一 JSON：成功包含 `status: "success"`；失敗包含 `status: "error"` 與可顯示訊息。
- 前端只有在收到成功 JSON 後才能顯示成功，不使用無法判斷結果的盲目成功流程。

## 前端調整

保留現有三個主要入口：

- 請假登記
- 尋找與領取代課
- 查看我的代課紀錄

領取代課畫面新增：

- 每筆課程顯示課程大類。
- 選擇代課老師後即時計算是否跨大類。
- 跨大類項目展開「改成什麼課」必填欄位。
- 同時勾選多堂課時，各堂跨大類課程需分別填寫備註。
- 送出期間停用按鈕，避免重複點擊。
- 後端回覆衝突時顯示「此代課已被其他老師領取」並重新整理待領取清單。

## 錯誤處理

- API 同步失敗：保留舊課程資料，記錄錯誤並終止本次同步。
- 試算表缺少必要工作表或標題：停止寫入並回傳明確錯誤。
- 老師名單或課程無法辨識：不允許提交。
- 網路錯誤：前端保留使用者選擇並提供重試。
- 同時領取衝突：只允許第一筆成功，其餘回傳衝突訊息。

## 驗證標準

- API 能分頁取得今天至下個月底的有效課程。
- API 失敗時 `CourseList` 不會被清空。
- A 至 I 欄既有欄位與固定索引不變。
- 同類課程可直接領取。
- 跨類課程未填備註時，前端與後端都拒絕。
- 跨類課程備註正確寫入 H 欄。
- 兩位老師同時領取同一代課時，只能有一位成功。
- 同一堂請假不可重複送出。
- 手機與桌面畫面均可完成請假、領取與查詢。
- 正式前端不含 API 權杖。
