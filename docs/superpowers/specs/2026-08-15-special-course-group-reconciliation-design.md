# 特別課群組 OB 核對設計

## 目的

同一堂特別課可能占用多個原代課時段。OB 只保留一堂實際特別課時，系統應以「特別課群組」核對，不應要求每個被占用的原時段都繼續存在。

## 核對規則

- 有「特別課群組 ID」的待核對紀錄，以群組為單位處理。
- 群組內只允許一個實際存在且符合預期代課老師與特別課名稱的 OB Calendar 課程。
- 找到一堂符合的實際特別課時，群組內所有被占用時段一起標記為「已核對／已完成」；後續原時段已取消或移除不算異常。
- 找不到任何符合課程時，整個群組維持「核對異常」。
- 同一群組若仍找到多堂 OB 課程，視為可能重複排課，整個群組維持「核對異常」。
- 沒有「特別課群組 ID」的一般代課，維持目前逐筆核對邏輯。

## 資料安全

- 不新增、刪除或搬動工作表欄位。
- 不改寫原始 OB Calendar ID、特別課群組 ID 或老師填寫內容。
- 只更新既有核對狀態、核對時間、異常文字與稽核紀錄。
- 所有群組狀態在既有 Script Lock 與回滾機制內一次完成。

## 驗證案例

- 三個原時段合併成一堂特別課，後兩堂已從 OB 消失：三筆皆核對完成。
- 群組完全找不到實際特別課：三筆皆顯示核對異常。
- 群組仍存在兩堂以上 OB 課程：三筆皆顯示重複排課異常。
- 一般代課缺少 OB Calendar ID：仍依原邏輯顯示核對異常。
