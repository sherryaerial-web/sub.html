# 第一輪關課文案傳送 LINE 設計

## 已確認的目的

冠蓉與 Tako 都已加入官方帳號。第一輪關課完成並產出徵人文案後（通常約 22:34），各收到一份純文字，方便在 LINE 轉貼社群。不是另設 22:30 或 22:34 定時推播，也不直接發 OpenChat。

## 範圍與實作方向

- GAS 沿用 `buildCourseClosureSocialCopy_` 與 `saveCourseClosureSocialCopy_` 的結果，不重查 OB、不改門檻、優惠課缺一／缺二規則或關課時間。
- 在第一輪工作完成、離開現有資料鎖後，將文案交給經驗證的 LINE 發送端。不得在每次儲存或管理員讀取文案時發送。
- 只傳給已綁定的冠蓉、Tako；不得呼叫廣播 API。不新增 AI 使用量。
- 文案為空時跳過。若關課有失敗項目，暫停自動傳送並記錄原因，避免將不完整結果當完成文案。
- 23:40 第二輪不發這份訊息。既有後台複製文字仍保留。

## 身分綁定

由管理端產生各自的高熵一次性驗證碼，綁定固定角色而非顯示名稱；有效期限 30 分鐘。只接受官方帳號一對一、LINE 簽章驗證通過的 webhook。核對並原子消耗驗證碼後，儲存該事件的 userId。

驗證碼僅儲存雜湊，不記錄原碼；到期、用過或群組傳入均拒絕。已綁定者不可被另一個帳號覆蓋，須經管理者撤銷後重新綁定。綁定指令在 AI 客服之前處理，不送給模型。

目前本機 LINE 設定名為 `sherry-line-ai-staging`，不能据此判定正式 webhook。啟用前須核對官方帳號 channel、正式 webhook 及對應 Worker。若正式 webhook 是另一服務，先提出該服務的綁定接入方式，不擅自切換 webhook 或覆蓋現有客服。

## 發送與防重複

GAS 到發送端使用獨立 secret 簽章、時間戳與重放檢查；密鑰存於 Script Properties／Worker secrets，不寫入前端或 Git。

以「目標課程日期＋第一輪＋收件角色」作為唯一送件鍵。發送端用持久化資料庫記錄狀態並原子領取工作，保存同一 LINE retry key；重試不得生成新 key。每個收件人獨立追蹤，成功者不重傳。相同鍵但不同內容不自動重發，另記錄內容不符供人工確認。

Worker 接收後持久化待送件，背景執行並有限重試暫時性錯誤；429 遵守重試間隔，永久錯誤停止。不能把 HTTP 200 當成使用者已閱讀或必定收到。逾 LINE retry key 有效窗口不盲目重送。

GAS 網路交付失敗不回滾或重新執行關課；保留待交付標記，後續排程僅補交相同送件鍵。須在 LINE 有效重試窗口內且早於當晚第二輪才自動補送，過期記錄失敗、不補發過時徵人文案。手動重新執行第一輪也遵守同一防重複鍵。

## 安全與驗收

- 新功能預設停用，綁定兩人後仍需正式部署與測試傳送授權。
- 不改 OB、現有試算表欄位或登記資料；通知狀態使用獨立儲存。
- 必測：空文案、第二輪、未綁定、綁定過期／重放／冒用、雙人各一次、單人失敗重試、逾時但 LINE 已接受、並行排程、重跑不同文案、發送故障不影響关課、補送過期。
- 發布前一次跑直接涉及關課與通知的完整回歸；相同已測版本不重跑。發布後核對 GAS／Worker 版本與設定，不為驗收而實際關課。
- 需使用者授權後才傳測試訊息；兩人確認收到再開啟自動發送。可立即停用發送旗標，不停用關課。

## 使用者操作

功能部署並核對 webhook 後，分別提供兩人的驗證碼，各私訊官方帳號一次；確認測試訊息。此後不需每日操作。

## 待部署階段確認的環境資訊

正式 webhook 接收服務、同 channel 的發送憑證、兩位完成綁定的 userId。不得從名稱推測或把 staging 憑證當作正式設定。
