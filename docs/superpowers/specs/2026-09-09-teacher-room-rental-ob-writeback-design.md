# 老師教室租借與 OB 回寫設計

日期：2026-09-09  
狀態：已完成對話設計，待冠蓉確認書面規格  
實作範圍：Sherry Aerial 老師端自主練習頁、GAS、獨立 Google Sheet 工作表、Omcean Booking API

## 1. 目標

讓已登入老師直接在現有自主練習行事曆登記教室租借。系統以租借課程決定固定時長，核對正式課程、既有租借、老師自主練習及學生自主練習後，將可成立的租借寫回 Omcean Booking（以下簡稱 OB）。

本功能不讓老師自行輸入或修改租借分鐘數，也不修改既有正式課程資料。正式課程仍是最高優先來源；租借低於正式課程、高於所有自主練習。

## 2. 操作入口與畫面

不新增側邊選單。現有「自主練習」頁繼續作為同一張教室使用行事曆，頁面上方提供兩個明確入口：

1. `＋自主練習`
2. `＋租借教室`

租借表單欄位為：

- 日期。
- 教室。
- 租借課程。
- 開始時間。
- 單次或每週循環。
- 循環結束日期；循環租借必填。
- 備註。

租借課程下拉選單只顯示 OB 課程名稱含「場地租借」或「場租」的課程。每個選項顯示課程名稱與 OB 設定的固定時長，例如 `場地租借 120 分鐘`。老師選擇課程後，系統直接使用該課程的 `classId` 與 `duration`；表單不另設 60、90、120、150 分鐘按鈕，也不允許自行輸入結束時間。

行事曆沿用既有類型與顏色，並清楚區分正式課程、場地租借、老師自主練習、學生自主練習及自己的登記。點選自己的租借可查看明細或取消；其他老師只能看見租借已占用，不顯示取消操作。

## 3. 權限

- 所有已登入且在職的老師都能登記及取消自己的租借，不需管理員事前審核。
- 老師只能取消自己的租借。
- 冠蓉與 Tako 可在管理端查看所有租借、候補、失敗與取消紀錄，並可代為取消。
- 不提供編輯租借。若要變更日期、教室、課程或開始時間，必須先取消再重新登記。
- OB 老師身分必須解析為唯一且穩定的 `instructorId`；無法唯一解析時禁止寫入，並通知管理員補齊對照，不可只以模糊姓名猜測。

## 4. 優先順序與緩衝

教室使用優先順序固定為：

1. OB 正式課程。
2. OB 教室租借。
3. 老師自主練習。
4. 學生自主練習。

正式課程與教室租借在衝突判斷時，前後都保留 15 分鐘緩衝。完整占用區間為：

`課程或租借開始前 15 分鐘` 至 `課程或租借結束後 15 分鐘`

租借時長只取自 OB 租借課程的 `duration`。例如老師可選 60、90、120 或 150 分鐘的租借課程；若需要兩段 60 分鐘，可以分別登記，兩段之間仍必須符合 15 分鐘緩衝，也可以直接選擇一個 120 分鐘租借課程。

不同教室互不衝突。相同老師在其他教室同時另有 OB 課程，若 OB 商家設定會檢查老師衝突，則以 OB 的 409 回應為最終結果。

## 5. 單次租借流程

老師送出前，後端必須在鎖內重新讀取目標日期的 OB 即時課表，不依賴畫面快取或最後同步的 `CourseList`。

### 時段沒有正式課程或其他租借

1. 驗證登入身分、租借課程、教室、開始時間與時長。
2. 核對 OB 正式課程及租借，加上前後 15 分鐘緩衝。
3. 收集會被取代的老師／學生自主練習，回傳確認摘要。
4. 老師確認「租借成立後會取消或標記受影響自主練習」後送出。
5. 在鎖內再次核對 OB。
6. 呼叫 `POST /v1/calendar`，傳入租借課程 `classId`、`classTime`、`classRoomId`、老師 `instructorIds` 與內部追蹤備註；單次租借不傳 `courseId`。
7. 只有 OB 回傳 201 且取得 Calendar ID 後，才將租借標記為已成立，並處理低優先自主練習。
8. 清除相關日期快取、更新行事曆並發送通知。

### 時段有正式課程

不得直接寫入 OB，也不得取消正式課程。系統改為建立「候補租借」，綁定造成衝突的 OB Calendar ID，並保存老師已選定的租借課程、時長、教室與開始時間。

### 時段有其他租借

不得覆蓋既有租借。系統建立候補租借，排序規則與正式課程候補相同。

## 6. 候補租借

- 候補不寫入 OB，也不占用教室。
- 相同日期、教室及實際占用區間重疊的候補，依建立時間與租借需求 ID 排序，最早者優先。
- 老師建立候補時，必須先同意：若上位課程或租借取消，系統會自動嘗試建立租借，且成立後可能取代同時段自主練習。
- OB 同步、每小時練習核對、管理員手動更新或正式關課完成後，都可觸發候補檢查。
- 上位項目取消後，系統在鎖內重新讀取 OB，再依序嘗試第一位候補。
- 第一位因 OB 409、資料錯誤或身分對照缺漏而建立失敗時，不得讓後位候補直接越過；先把該筆標記為「成立失敗待處理」並通知本人與管理員，避免不明確搶位。
- 第一位主動取消候補後，下一位才可遞補。
- 候補日期或開始時間已過時，自動標記為過期，不再嘗試寫入。

## 7. 自主練習被租借取代

老師確認租借或候補登記時，畫面必須列出會受影響的自主練習時段與人員摘要。

租借成功寫入 OB 後才進行下列處理：

- 衝突的老師自主練習標記為「衝突取消」，保留原場次、參與者與稽核資料，通知所有受影響老師。
- 衝突的學生自主練習標記為「時段異動待處理」，不直接刪除或假設已通知學生；通知冠蓉與 Tako，內容包含學生 APP 名稱、Email、原日期、教室及時間，供後續聯絡、換時段或退點。
- 受影響資料使用場次唯一 ID 精準更新，不清空、不搬移、不覆蓋整張工作表。
- 若 OB 建立失敗，自主練習維持原狀。

## 8. 每週循環

- 循環租借必須指定結束日期，不建立無期限循環。
- 每一週都是獨立的租借需求與 OB Calendar ID；系列只保存共同規則。
- 系統逐週核對與建立：可用週次直接寫入 OB，有正式課程或既有租借的週次建立候補，不影響其他週次。
- 某週會取代自主練習時，該週個別列出影響並要求老師在整批送出前一次確認。
- 批次處理採有限速的逐筆請求，不得同時大量呼叫 OB；遇到 429 時停止剩餘寫入，保留未處理狀態並依 `Retry-After` 或下次排程重試。
- 取消循環時提供「只取消本次」及「停止本次以後」。每一筆已成立租借都必須逐堂呼叫 OB 取消 API；OB 確認取消前，本地不得顯示已取消。

## 9. 取消規則

- 取消候補只更新本地候補狀態，不呼叫 OB。
- 取消已成立租借呼叫 `POST /v1/calendar/{id}/cancel`。
- OB 取消 API 可安全重試；成功後保留已取消 Calendar ID 與時間，不刪除歷史紀錄。
- OB 取消失敗時，本地租借維持已成立，顯示明確錯誤並通知老師與管理員。
- 取消成功後清除相關日期快取，再依順序檢查其他候補。
- 不支援把已取消的 OB 時段重新開啟；重新租借必須建立新時段。

## 10. OB 資料與 API 契約

使用具讀寫權限的 Bearer Token，且 Token 只保存於 Apps Script Script Properties，不寫入前端、Git 或 Sheet。

需要的 OB 資料：

- `GET /v1/classes`：取得租借課程的 `classId`、名稱與 `duration`。
- `GET /v1/class-rooms`：取得 A／B／C／D 對應的 `classRoomId`。
- `GET /v1/instructors`：取得老師穩定的 `instructorId`。
- `GET /v1/calendar`：送出前即時衝突核對與失敗重試前防重複查詢。
- `POST /v1/calendar`：建立單次租借時段。
- `POST /v1/calendar/{id}/cancel`：取消已成立租借。

OB 建立 API 沒有結束時間欄位；結束時間必須由所選租借課程的 `duration` 計算。OB 回傳 409 時視為上位項目衝突，禁止在本地標記成功。

系統以租借需求 UUID 寫入 OB `privateNotes`，例如 `Sherry rental request: <UUID>`。若 OB 已成功但本地寫入中斷，重試前先以日期範圍重新讀取 OB，比對 Calendar ID、日期、教室、classId、老師及追蹤 UUID，防止重複建立。

## 11. 資料模型與 Sheet 安全

新增獨立工作表，不修改既有 `CourseList`、自主練習、學生自主練習、請假、代課、薪資或 VVIP 欄位順序：

1. `教室租借系列`：系列 ID、老師、租借 Class ID、教室、星期、開始時間、生效日期、結束日期、狀態、建立與更新資訊。
2. `教室租借需求`：需求 ID、系列 ID、老師、OB 老師 ID、日期、教室、OB 教室 ID、租借 Class ID、租借課程、分鐘數、開始與結束時間、狀態、候補衝突 Calendar ID、OB Calendar ID、失敗原因、建立與更新資訊。
3. `教室租借操作紀錄`：時間、操作者、動作、目標類型、目標 ID、修改前後 JSON、原因。
4. `OB租借對照`：對照類型、系統名稱、OB ID、OB 名稱、狀態、更新時間、更新者；用於無法由既有穩定 ID 安全解析的老師與教室。

租借需求狀態固定為：`待確認影響`、`待寫入`、`候補`、`寫入中`、`已成立`、`成立失敗待處理`、`取消中`、`已取消`、`過期`。

所有多表寫入使用 `LockService`，以唯一 ID 找明確列並作最小更新。不得整張清除或覆寫人工資料。`CourseList` 仍只是 OB 快照，不作為租借交易紀錄。

## 12. 通知

通知老師的事件：

- 租借已成立。
- 租借進入候補。
- 候補轉為已成立。
- 自己取消成功或取消失敗。
- OB 寫入失敗、身分對照缺漏或循環部分失敗。
- 自主練習因租借成立而取消。

通知冠蓉與 Tako 的事件：

- 學生自主練習因租借而進入「時段異動待處理」。
- OB 寫入／取消失敗。
- 老師或教室 OB ID 無法唯一解析。
- 循環租借因限流而留下未完成項目。

通知寫入現有訊息收件匣並依既有 OneSignal 流程推播。推播失敗不回滾已成功的 OB 交易，但必須留下可追蹤的通知失敗紀錄。

## 13. 錯誤處理與一致性

- OB 即時讀取失敗：禁止新建或自動遞補，不使用舊快取猜測可用；既有租借與自主練習不變。
- OB 401／403：顯示系統設定錯誤並通知管理員，不重試寫入。
- OB 409：保留或建立候補，不顯示假成功。
- OB 429：停止該批後續請求並延後重試，不密集重呼。
- OB 5xx 或網路不確定：先把需求保留為待確認，不直接重送；重新讀取 OB 確認是否已建立後才決定重試。
- Sheet 寫入失敗但 OB 已建立：以追蹤 UUID 與 OB 即時資料進行復原，不再次建立相同租借。
- 同時多人操作：在鎖內重新核對候補順序與 OB 課表。
- 低優先自主練習只在 OB 明確建立成功後異動。

## 14. 測試與驗收

### 課程與時間

- 租借選項只出現 OB 場地租借／場租課程。
- 選擇課程後正確帶入 60、90、120、150 分鐘等 OB `duration`，且老師無法另外修改分鐘數。
- 正式課程與租借前後 15 分鐘邊界正確；不同教室不互相阻擋。
- 送出前後 OB 資料變動時，以鎖內最新結果為準。

### 直接成立與候補

- 空檔租借只在 OB 201 後顯示已成立並保存 Calendar ID。
- 正式課程或既有租借衝突時不寫 OB，改為候補。
- 多位候補依建立時間與需求 ID 排序，前位取消後才輪到下一位。
- 前位寫入失敗時停在待處理，不讓後位無聲越過。
- 過期候補不再執行。

### 自主練習

- 老師確認前顯示所有受影響老師／學生摘要。
- OB 建立失敗時不改自主練習。
- OB 建立成功後，老師自主練習轉衝突取消並通知老師。
- 學生自主練習轉時段異動待處理，只通知冠蓉與 Tako，不刪除學生資料。

### 循環與取消

- 循環必填結束日期，每週逐堂判斷為成立或候補。
- 單週衝突不影響其他週次。
- 只取消本次與停止本次以後只處理正確範圍。
- 已成立租借在 OB 取消成功前維持已成立。
- 取消後依序處理下一位候補。

### 安全與回歸

- 重複送出、網路逾時、OB 201 後本地失敗均不建立重複租借。
- 401、403、409、429、5xx 都有明確狀態與通知。
- 所有 Sheet 更新只影響目標 UUID 列。
- 現有老師自主練習、學生自主練習、代課、請假、薪資、VVIP、登入及通知測試維持通過。
- 手機 320、375、390、430px 下表單不破框，按鈕與課程時長清楚可讀。

## 15. 上線邊界

1. 先完成自動測試與測試資料驗證，不寫正式 OB 或正式 Sheet。
2. 確認目前 `OMCEAN_API_TOKEN` 具讀寫權限；若需更換，只更新 Script Properties。
3. 使用測試老師、未來日期及明確測試租借課程完成一次建立與取消驗證。
4. 正式建立新 Sheet 前先讀取現況，只新增缺少的工作表與表頭。
5. 正式 OB 寫入測試、GitHub `main` 推送、`clasp push --force` 與 GAS 正式部署必須分別取得冠蓉明確允許。
